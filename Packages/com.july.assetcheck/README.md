# July 资源工具

Unity 2022.3 编辑器资源工具。统一入口：**JulyGF → 资源管理 → 资源工具**，包含资源检查、平台配置复制、打包分析、构建资源大小和字体检查。目录与忽略名单用于普通资源检查和配置复制；打包分析检查完整报告收录清单；字体检查使用独立来源列表。各页任务互斥并支持取消。UI Toolkit，仅 Editor，无运行时代码。

声明 July Logging 及 Unity 内置 Audio、JSON 模块依赖；通过 Git 安装时需显式添加 `com.july.logging`。未使用 URP 的项目也可以安装。

## 构建资源大小

入口：**资源工具 → 构建资源大小**。自动采集成功的客户端资源构建报告，打开页面和刷新只读取缓存，不发起构建。构建失败或仅脚本构建（包括 HybridCLR 生成裁剪 AOT DLL 的临时 Player）不更新资源记录。

从 `BuildReport.packedAssets.contents` 按源 GUID（无 GUID 时按路径）汇总物理入包记录，按大小降序显示名称、路径、报告类型、未压缩大小和占比，支持搜索、当前工程缩略图及 GUID 定位。占比以所选报告已统计的资源为分母，搜索不改变分母。Unity 构建总大小不代表平台最终首包或下载量；源文件大小不能代替入包大小。

缓存规则：
- 成功但无明细：保留已有列表和原构建来源，单独提示最近内容构建未提供明细。
- 成功且有增量明细：显示该报告，明确可能只含部分数据文件；保留此前完整构建报告，可直接切换查看。
- 成功的完整资源构建（CleanBuildCache，且非仅脚本）有明细：替换保留报告并清除旧增量记录。完整构建提供的明细也不保证覆盖最终平台包的全部组成。
- 不跨构建拼接资源；列表、大小、时间、平台及输出路径始终属于同一份报告。不同构建目标分别保存。

每个目标最多保留一份完整构建明细和一份后续非空增量明细，位于 `July/AssetCheck/PlayerBuild/<BuildTarget>.json`。读取旧 `Library/July/AssetCheck/PlayerBuild/latest.json` 时保留其原信息，标明覆盖范围未记录；查看不写文件，下次成功内容报告才保存到新位置。首次没有任何可用记录时，需要通过现有出包入口进行完整资源构建。工具不会为了查看缓存自动要求全量；只有需要最新资源数据、当前报告又无法提供时，才考虑完整构建。

资源数据在构建回调中提取，待构建结束后确认最后一份内容报告的结果、完成时间和总大小。现有 YooAsset AB 分析保持独立。

## 字体检查

入口：**资源工具 → 字体检查**。只读检查 JSON 及指定目录中的 Prefab／场景 TMP 文本，不扫描代码，不推断运行时赋值、格式化参数或最终渲染效果。

### JSON 来源

首次进入自动发现 `Assets` 下文件名包含 `language`（大小写不敏感）的 JSON，按 GUID 保存来源列表。可手动添加 Assets 下的 JSON、移除来源；刷新只加入新发现项，保留手动排除记录。字符文件可拖入 JSON；首次配置发现唯一 `tblanguage.json` 时自动选中。

先解析 JSON，再递归收集全部字符串值（包含 Key／Id 对应的字符串，不收集属性名、数值、布尔或 null），解码 Unicode 转义和补充平面字符，忽略控制符。全字符串检查仍包含业务标识和富文本标记。分别与字符文件、TMP Settings 默认字体当前字符表比较。字符文件同时也是来源时显示同源提示，该文件与自身的对照没有独立校验作用。

### Prefab／场景目录

通过“添加扫描目录”选择一个或多个 Assets 目录，递归查找 `.prefab`、`.unity`，重叠目录中的文件只扫描一次。目录按 GUID 保存，可移除；不使用普通资源检查范围或忽略名单。包本身不预设游戏目录；没有目录时保持仅 JSON 检查，也可移除所有 JSON 来源，仅检查 Prefab／场景。

读取非空 TMP 文本，包括未激活对象、嵌套 Prefab、变体及场景实例最终生效的覆盖值。按组件指定字体检查，未指定时采用 TMP 默认字体；失效引用不自动改用默认字体。Prefab／场景文字只与实际字体比较，不要求收录进 JSON 字符文件。

按组件 richText／控制字符设置处理常用 TMP 标签、noparse、转义及补充平面字符；常用颜色、链接和排版标签不计为显示字符，sprite 标签不计为字体字符。未识别标签保留为普通文字。字体切换、样式、自定义组件文字样式及大小写转换不展开，整段列为“未验证”，不计入覆盖通过。此检查不验证备用字体、替代字重／字形或 sprite 资源有效性，不触发 TMP 排版或动态补字。

同对象上存在 `July.Localization.UILocalizedText` 时，通过类型全名标记为“本地化组件默认文字”，不调用本地化运行时，也不增加 Localization 包依赖；正式文案继续由 JSON 来源检查。

沿用 July 的公开场景读取流程：未打开的场景临时附加打开，立即恢复活动场景和选中对象，同步采集文字后关闭，再让出执行权。Prefab 使用隔离内容加载并在采集后立即卸载。已打开且未保存的场景／Prefab 模式列为“未验证”，请保存后重新检查；不扫描未保存版本。不保存或修复资源。用户点击结果的“定位对象与组件”时，才打开 Prefab 模式或保留打开的目标场景。

### 结果与生命周期

窗口采用配置／结果双栏，检查按钮、状态和进度固定在顶部；窄窗口上下排列，两侧内容分别滚动。默认字体、JSON 文案与界面扫描目录分区展示，详细规则默认折叠；深浅编辑器主题分别适配。结果保留缺字汇总、字体分组、对象层级及来源定位，过期和未验证状态明确标记。

按字体显示所需字符数、缺字、文件／对象层级／组件与来源定位；JSON 字符文件缺字单独显示。顶部保留一份合并去重的缺字及复制入口。未验证文本明确列出原因；没有可比对文字时不宣称覆盖完整。缺字只表示目标字体当前字符表未包含，不能据此断言动态或备用字体在运行时一定显示失败。

任务按文件／文本推进，支持取消和关闭清理，与其它资源工具任务互斥。单个资源的同步加载与采集期间无法中断。读取或 JSON 解析失败明确显示文件路径，不生成完整结果；重试成功清除旧错误。输入资源、已记录依赖、扫描范围内新增 Prefab／场景、默认字体或配置改变后结果过期，禁止复制。修改已打开的扫描场景也会使结果过期。

共享配置位于 `ProjectSettings/July/AssetCheck/settings.json` 的 `fonts` 字段：JSON 来源、字符文件及排除记录保持，新增 `scanFolderGuids` 保存独立扫描目录。检查结果仅存在于窗口会话中。

## 分析已有打包报告

选择已有 YooAsset 2.3.x `.report`，点击一次“开始分析”：先显示AB分析，再自动检查入包资源当前配置及源文件内容重复。报告通常位于 `Bundles/<平台>/<Package>/<版本>/<Package>_<版本>.report`。不构建、不加载二进制AB、不改资源或打包配置。

### AB包结果

报告导入、历史记录和构建入口分行显示；包体概览、结果切换与筛选分区呈现，详情独立滚动，较矮窗口使用紧凑布局。深浅主题沿用编辑器配色，分析、检查及比较算法不变。

默认显示包名、自身文件大小、依赖包数、含依赖总计及标记。支持按自身大小、依赖数量、总大小排序和搜索／标记筛选。默认最小32 KiB，最大3 MiB，可通过“AB大小标准”调整；严格低于／高于才标记过小／过大，等于边界不标记。标记只供核查，不阻断发布。

包级依赖按报告关系展开，依赖数不含自身，含依赖总计包含自身且按包去重。B、C均依赖D时，两条关系保留，但D的数量／字节只计一次。选中包可查看依赖、谁依赖此包、包内资源及其检查结果。包内资源名称点击后选中并 Ping 当前资源，保持在 AB 页；右侧独立的“查看检查结果”按钮转到该资源所属分类、展开并滚动到对应结果，保留本包大小口径，同时清除可能遮住目标的目录、搜索、状态和问题类型筛选。数据是包文件合计，不是实际下载量或内存；不引入Tag、缓存和业务下载流程，也不混入单资源加载集合。

循环依赖在包列表中标记，仅展开时显示具体循环路径和报告资源关联。读取报告的 `DependAssets` 及归属记录解释致因；关系可能是间接依赖，不伪造直接引用层级或历史对象字段。无法定位时明确“报告未提供”，不拿当前工程引用冒充历史构建证据。成环不自动认定运行死锁。

### 资源检查结果

以报告主资源和包内内容为范围，按GUID匹配当前工程；无GUID时显式按路径匹配，同路径不同GUID不误定位。相同资源在多个包中出现只检查一次，关联全部所属AB；适用的多个模块／子资源检查共用既有规则。缺失、不支持及规则未能验证的情况明确列出，不计通过。

入包检查不应用普通目录及忽略名单；普通资源检查和复制原有忽略功能保持。贴图／图集沿用WebGL、MiniGame、WeixinMiniGame三平台标准，其他类型沿用现有规则，后续通用规则扩展由两个入口共同复用。入包任务不改scope、不清空忽略、不覆盖普通检查报告，不提供修改选中／全部入口。

资源结果直接扩展既有资源检查的分类页签与结果表格，按贴图（含图集）、模型、材质、预制体／场景、音频等分类查看；文件多项问题在表格内展开，直接列出问题、当前值和要求，保留排序、问题类型筛选、缩略图与点击定位。AB追加“所属AB”关联列及重复候选证据详情；不提供修复、忽略或右键写入操作。缺失和无适用模块的文件在“未归类”入口保留。

分类由检查模块的实际适用性与执行结果确定，不能仅按扩展名或问题推导。同一文件可接受多个分类检查，各分类独立统计、显示本分类问题；全局按资源身份去重，分类数不相加当总数。通过、违规（可含未验证）、优化候选、未能检查和未完成分别表达，候选可与违规重叠；查重未完成不计完整通过。切分类只读取已有检查快照，不触发重新扫描。普通检查的修复／忽略与报告生命周期保持。

两类优化候选：同一资源跨包分别收录；不同资源文件的源内容完全相同。正常共享包引用不算重复收录。内容比较只处理当前入包集合，按文件长度／内容哈希分组，不做图像相似度、不把meta当源内容，不推算节省字节，不自动合并；导入设置和用途仍需人工核对。

### 快照与取消

AB大小、依赖和归属固定来自读取的report，读取新构建report才反映新构建结果。资源检查与内容比较是分析时当前工程的快照，显示检查时间，不还原构建时配置。后续修改资源不会改写本工具已有结果；资源问题修复后的复查使用现有资源检查，不在构建分析中新增实时复查流程。

显示阶段与进度，可取消／关闭，保留已完成结果，剩余明确未完成；不会把取消计为通过。执行期间资源／配置改变或规则失败会停止相应检查并显示原因，已读取AB事实保留。配置被外部修改后，需通过共用设置重新加载才能开始新的分析，不删除已完成快照。

配置版本5迁移保留原标准与忽略历史，增加AB阈值、Sprite／图集MipMap允许项（默认关闭）及Mesh子网格上限（默认4）。这两条通用规则在现有资源检查中实现，本工具复用；不增加自动修复。打入图集的Sprite由图集MipMap设置判定，普通3D纹理不一刀切禁用MipMap。

验证：Unity 2022.3.62f2 隔离工程完整回归 **240 Passed / 0 Failed / 0 Skipped**，覆盖完整入包集合、普通忽略隔离、多模块子资源、配置迁移、规则一致、循环及报告致因、排序身份、取消与内容检查未完成状态、变体主图集MipMap及缺失、文件流释放和原生窗口布局。真实report只读对照442包、5227资源、189933430字节，报告文件未变。

## 复制 WebGL 平台配置

入口：**资源工具 → 平台配置复制**。页面按扫描操作、扫描／差异／一致／选择概览、筛选与复制操作、差异表格和底部状态组织；资源行带缩略图，差异目标以主题适配颜色标记，规则默认折叠。使用窗口顶部的共享目录，按“选择文件夹 → 扫描 → 列出差异 → 复制”操作：拖入 Assets 下的文件夹，或在 Project 中选目录后点击“使用选中目录”；也可选择“全部 Assets”。选择目录及打开窗口不自动扫描，也不修改资源。

点击“扫描”后，分批读取目录内导入贴图及 SpriteAtlas 的 WebGL、MiniGame、WeixinMiniGame 配置，列出文件、WebGL 来源及两个目标的当前配置与一致状态。默认仅显示差异，可切换显示全部。悬停查看参数详情，左键点击每行的文件名、路径或任一平台配置单元格，都会选中并 Ping 对应资源；复选框仅用于勾选。资源移动后按 GUID 定位，已删除资源不再定位。不支持没有 TextureImporter 的原生纹理资产。

扫描完成后可勾选文件并“复制选中”，或“复制全部差异”。复制每个资源的 WebGL 平台参数，包括尺寸、格式和压缩质量。更换文件夹后须重新扫描；目录内资源导入、移动或删除会令列表过期并停止后续任务，重新扫描后才能复制。复制完成自动重新扫描，以实际保存后的配置更新列表；勾选按文件 GUID 保存，筛选不会转移勾选对象。

WebGL 未启用平台覆盖时，复制继承的 Default 参数，在两个目标启用覆盖。Automatic 保持原值，由目标平台解释，不推断实际压缩格式。只复制平台参数，不修改 WebGL、Default、其他平台、源图、图集打包对象或检查标准，也不执行图集打包。

复制扫描和执行均沿用资源检查的同一忽略名单：单文件按 GUID，目录递归覆盖子资源，移动或改名后仍按 GUID 识别。被忽略的贴图和图集不会列为待复制项，统计中显示忽略数量。执行前重新核对名单，即使传入旧扫描路径也不复制已忽略文件。添加或恢复忽略项后，复制页清空旧结果并要求重新扫描；配置文件被外部修改时暂停复制，须重新加载配置后扫描。

扫描、复制每批最多 20 个文件；扫描只读，复制在批次结束后集中导入并更新进度，相同配置不重复保存或导入。可在批次之间取消；关闭窗口也会停止后续批次。未完成或过期的扫描不允许复制。取消或失败保留已经保存的修改，失败在窗口和 Console 显示。建议先提交资源配置，便于按版本控制查看与恢复结果。

## 使用

1. 公共平台默认「小游戏」，纹理目标明确包含 WebGL、MiniGame、WeixinMiniGame。项目配置的构建目标按引擎确定：普通 Unity 使用 WebGL，团结 TUANJIE_1_5_OR_NEWER 使用 MiniGame，不切换当前构建目标。
2. “资源检查”页签保留七个资源类型 Tab：贴图、模型、材质、预制体／场景、音频、URP、项目设置。检查当前类型或检查全部；注册且适用的规则全部执行，不提供规则启停开关。
3. 资源目录限制普通资源收集；URP 按 Graphics 和目标平台启用的 Quality 档收集关联管线及 Renderer，项目设置始终检查全项目配置。不会递归扫描目录外的普通资源依赖。
4. 每类标准在折叠区域修改。允许格式以集合设置，修改目标单独选择。只展示问题和未能验证的结果，通过仅计数；没有搜索、详情页或严重程度。
5. 结果以文件为主行，单问题直接显示，多问题内联展开；文件名优先，目录按列宽显示，空间不足时才省略前段，悬停显示完整路径。贴图、模型／Mesh 和材质类型的文件主行显示 32×32 缩略图，保持原图比例和透明度；普通贴图直接显示已导入纹理，模型、材质和图集使用 Unity 原生异步预览，不可用时显示资源图标，不主动打包图集或修改导入设置；复合资源文件显示该文件的整体预览。仅按可见虚拟行加载，行复用时清空旧预览，资源移动后按 GUID 更新，展开的问题子行不重复显示。点击缩略图或文件名直接选中资源，子问题名称可定位具体对象；文件主行直接显示“忽略”，按整个文件跳过检查。文件、问题、当前值、允许／要求四列表头均可点击排序，再次点击切换升降序，数值按大小比较。文件保持分组，多问题文件使用该列最小值排序，组内问题也按该列排序。支持问题类型筛选。筛选不关闭规则。勾选按文件标识保存，排序不会把选择转移到其他文件，筛选或换报告清空选择。仅未验证文件默认折叠，混合结果不重复计文件。Tab 有报告时始终显示问题文件数量，过期仍保留原数字和结果列表；没有检查记录显示“—”。当前页总览及悬停提示说明过期后需重新检查才能修改，修改权限及报告失效机制保持。“修改全部”处理当前 Tab 的全部已确认可修改问题，不受筛选和折叠影响；“修改选中”只处理勾选文件中符合筛选的已确认问题；未验证目标通过“设为标准”或右键菜单明确处理。
窗口沿用 Unity 原生字体与控件，提供深浅主题配色。顶部集中平台、范围与检查入口；Tab 数字仅表示已确认的问题文件数，概览单独显示问题、仅未验证、通过及忽略。上次快照与过期等状态独立提示。点击文件名选中资源，忽略直接显示为文件主行按钮；未验证目标仍可通过右键明确设为标准。配置文件和报告目录收进设置菜单。

6. 在 Project 中右键 Assets 下的具体文件夹 → **JulyGF → 资源检查 → 忽略文件夹／取消忽略文件夹**，支持多选目录。同一批选择父子目录时只新增最上层目录记录，和选择顺序无关；之前单独建立的子目录记录保留。单选未忽略目录仅启用“忽略”，已有独立忽略记录仅启用“取消忽略”；多选状态混合时两项均可用，仅处理对应状态的目录。继承上级忽略且没有独立记录的子目录两项均不可用，需在对应上级取消；展开右键菜单只读取配置，不创建或升级磁盘文件。目录忽略递归作用于全部类型，以文件夹 GUID 保存，移动或改名后仍有效；同名路径前缀不会误匹配。取消只移除所选目录自身的记录，保留上级、子目录和单文件的独立忽略；要恢复被上级覆盖的目录，请在对应上级取消。可在窗口的“已忽略资源”中查看与恢复。操作后重新扫描更新结果；检查或修改期间禁止变更目录忽略。不修改资源文件。

7. 当前报告可定位到子 Mesh／材质和问题组件；过期报告不按旧层级定位组件，仍可定位资源文件或有效子资源。可以单条修改、修改选中项、修改当前类型全部可修改项。修改前重读状态，只修改仍然不符合标准的对应设置，同一文件合并保存／导入；贴图（含图集）每批最多处理 20 个文件，通过 Unity 原生批处理集中导入，结束本批导入后更新进度并允许取消，所有批次结束后复查。每批通过 finally 恢复导入，取消或失败保留已保存的修改；当前批次导入期间仍可能阻塞。其他类型保持原有逐文件处理。

普通贴图与图集的 MiniGame、WeixinMiniGame 未启用平台覆盖时，显示“未配置平台覆盖”，计为问题并纳入“修改全部”。已配置且允许的格式保留；已启用覆盖但 Automatic 无法解析的目标仍为未验证，不随“修改全部”改写，可明确“设为标准”。WebGL 保持按有效格式检查，不强制建立覆盖。

## 完整性与扫描边界

- 正常未赋值的对象引用不报错；问题行包括对象层级、组件和字段。
- 嵌套／场景 Prefab 的继承问题归源资源，使用者的覆盖问题归使用者，避免重复报告；源资源不在扫描目录时不会为了它自动扩大扫描范围。
- 当前有未保存修改的场景或 Prefab 模式资源标记未能验证。未打开的场景以 additive 方式临时读取，随后关闭且不保存；保留原有场景、活动场景和选择。层级遍历分批执行，可中途取消并清理临时场景；Unity 原生打开／导入单次调用仍可能阻塞，也无法隔离项目自带的编辑器回调。
- 普通 Unity 无法解析团结目标 Automatic 或图集 Automatic 未得到有效格式时明确标记未能验证，可按明确标准写入覆盖后复查；扫描不会主动打包图集验证。
- URP 使用 Unity 2022.3／URP 14 的已知序列化字段读取配置。缺失字段标记未能验证，不反射猜测版本；不需要对 URP 程序集的编译依赖。光源枚举编码集中转换，保留配置 JSON 的既有语义；按 Forward／Forward+／2D 判断光照规则是否生效。Forward+ 与附加光源标准冲突时要求人工调整 Renderer，不提供无效的开关修改。批量修改先处理光源模式，再判断从属阴影参数，保留已失效功能的原有参数。
- 三角面统计不为检查开启 Read/Write，四边形计作两个三角面。独立 Mesh 不执行模型导入规则。

## 项目规则扩展

在项目的 Editor 程序集中引用 `July.AssetCheck.Editor`，实现所需 Context 的规则接口即可参与检查，无特性、手动注册、规则 ID 或版本配置：

```csharp
internal sealed class ExampleLayerRule : IAssetCheckRule<PrefabSceneCheckContext>
{
    public void Check(PrefabSceneCheckContext context)
    {
        if (context.IsPrefab && context.GameObject.name == "Example" && context.GameObject.layer != 31)
            context.Report(context.GameObject, "layer", "节点图层错误",
                context.GameObject.layer.ToString(), "31", "m_Layer");
    }
}
```

- Workspace 拥有 Module，Module 拥有规则实例。静态缓存仅保存发现的类型与构建标识；内置、项目规则统一发现、创建和执行，无两份注册表或合并排重。
- 问题统一由 Context 收集，在加入结果时校验修复条件并关联产生规则。规则无法直接访问结果列表；内置稳定标识与项目 `Report` 共用同一收集路径，调度器不再事后遍历结果补写归属。
- 一个 Module 固定一种 Context：`TextureCheckContext`、`ModelCheckContext`、`MaterialCheckContext`、`PrefabSceneCheckContext`、`AudioCheckContext`、`UrpCheckContext`、`ProjectCheckContext`。规则不加载资源、不保存 Context，也不修改检查输入。
- 所有非抽象、封闭的规则实现都参与发现，访问权限不决定是否启用。具体规则必须提供无参构造（可以非公开）；构造契约或规则执行失败明确中止检查。规则之间不依赖执行顺序。
- 模型导入选项与 URP 数值表是规则内部的参数化检查项，不实现规则接口。一个规则可以报告多条问题；原内置问题标识、平台目标及修复语义保留。
- `TextureCheckContext` 用 `IsAtlas` 区分图集与导入贴图，分别提供 Atlas 或 Importer；启用图集源图无压缩标准后，`IsAtlasSource` 标识被图集收录的 Sprite 纹理。归属索引由 Module 持有，资源导入／删除／移动后重建；查询目录外图集只用于判定归属，不扩大结果或修改范围。扫描不触发图集打包。`UrpCheckContext` 提供当前 SerializedObject，以 `IsPipeline` 区分管线与 Renderer；Facts 仅在管线结构验证成功时提供。
- `Report` 的 code 在当前规则内保持稳定；框架自动补充程序集／类型标识、文件标识和对象位置。框架不会按继承关系自动过滤项目规则：内置引用完整性规则继续归属源 Prefab，而依赖使用者层级的业务规则可以报告继承节点。
- 需要修复的规则可实现 `IAssetCheckFix<TContext>`，并以 `canFix: true` 报告可修复项。当前支持保存修改的 Module 是贴图、模型、URP；其余 Module 保持人工处理。修复由产生当前问题的规则执行，沿用修改前重新检查、平台目标限制、保存／导入和修改后复查。
- 报告上下文包含参与规则的类型及程序集构建标识；重新编译、添加或移除规则后，旧快照会要求重新检查。

## 修改与忽略

资源修改影响它的全部使用者，目录范围不会限制共享资源的影响。Read/Write 关闭可能影响运行时 CPU 读取；关闭导入灯光／相机／碰撞体或 URP 功能可能改变行为及画面。

普通 Unity 2022.3 的纹理接口会对团结目标 ASTC 写入报错。团结目标沿用原有实现：由原生接口初始化条目，再用 SerializedObject 仅修改已有条目的标量字段，不增删序列化平台数组、不反射、不编辑 meta 文本、不抑制错误日志。只改尺寸时保留原来的格式。

忽略记录可指向**整个文件或文件夹**，跨类型、跨平台生效；目录记录递归覆盖其下资源。普通资源按 GUID 跟踪移动或改名，ProjectSettings 按稳定的项目相对路径记录。忽略后跳过全部规则，不计通过，全局名单在每个 Tab 折叠展示且可恢复。忽略模型文件同时排除该文件中的全部 Mesh、导入检查及其他适用检查；没有按规则忽略和自动失效。文件和目录的直接／继承排除共用 AssetCheckExclusions；已被目录覆盖的旧问题不会再生成冗余单文件记录。恢复不存在的记录是无副作用操作。被上级目录覆盖的独立记录显示“仍被上级目录忽略”，按钮为“移除记录”，并提示具体上级来源；已删除资源也可移除记录。

## 配置与报告

窗口首次打开创建 `ProjectSettings/July/AssetCheck/settings.json`，可纳入 Git。最近扫描目录独立保存在 `Library/July/AssetCheck/state.json`，切换目录不改写项目检查标准或忽略名单。只读取当前配置版本5，不自动升级旧格式。修改目标必须属于允许集合，已允许的8×8不会被改成6×6。无效 JSON、Git 冲突、未知版本和外部修改不会被默认配置覆盖。

忽略变更立即清理内存和保存结果中已知的被忽略问题，并更新可准确计算的文件统计；报告过期时清空旧勾选。恢复及目录范围变更仍需重新扫描。快照没有通过文件的完整标识，无法准确重算的统计明确标记过期，不伪造新结果。报告上下文包含顺序无关的忽略名单标识，关闭窗口期间修改名单也会在重开时识别；载入时按当前名单清理旧问题，但保留原扫描范围和标准上下文。URP 等全项目类型也跟踪已收集但被忽略的输入，移出忽略目录时，无论扫描中还是扫描后都使结果过期。

启用图集源图标准时，扫描范围外的图集新增／修改／删除也会使贴图报告过期。标准、范围、资源导入／删除／移动、已检查依赖变化、场景未保存修改和外部配置变化会使相关报告过期，报告显示扫描时间；过期状态只能由重新检查解除。全项目配置报告不因普通资源目录变化而过期。报告会区分通过、问题、忽略和未能验证，记录取消／未完成／失败，过期或未完成报告不能用于修改。操作显示修改／跳过文件数和复查结果；取消或失败前已经保存的修改保留，并明确提示重新检查。扫描结果自动保存到 July/AssetCheck/Reports，每模块一个固定 JSON（Texture、Model、Material、PrefabScene、Audio、Urp、Project），只覆盖该模块的最新结果，不记录历史，也不写入 Git 管理的项目配置。开始新检查时写入 Scanning 状态，完成／取消／失败时更新最终状态和已完成文件的结果；忽略和报告过期也同步保存。文件记录原扫描平台、范围、标准上下文、时间、统计和问题行，打开窗口自动恢复为只读快照；快照不能触发修改，必须先重新扫描。只读取当前报告格式2，保留各目标的未验证状态，防止修改范围混淆。缓存损坏按模块明确提示，不覆盖原文件，也不影响其他模块。关闭窗口后不持续监听新变化。写入采用临时文件替换，保存失败明确提示并保留内存结果。共享检查快照可随项目提交 Git；删除 Library 不会清除这些快照。Tab 和折叠状态放在 SessionState。

## 扩展方式

- AssetCheckWorkspace 只负责配置、任务、忽略、报告和完整修改流程；AssetCheckWindow 负责公共展示与用户操作。
- IAssetCheckModule 维持 Collect／Check／Fix 三个入口。收集返回检查对象标识，普通资源是 GUID，项目配置是稳定路径，AssetCheckTarget 统一解析，不伪造 GUID。
- 新增规则实现对应上下文的 IAssetCheckRule<TContext>，提供无参构造，即可由 Unity TypeCache 自动发现；需要修复时实现 IAssetCheckFix<TContext>，且模块本身必须允许保存。项目编辑器程序集中的规则同样可被发现。类型自行读取事实，规则自行判断，各类型不需要采用同一种事实结构。规则实例归各模块和工作区所有，只共享不可变的发现元数据。
- 新类型增加 Kind 与必要标准、实现模块、在所属类型目录提供标准表单，在 AssetCheckCatalog 一次注册名称／范围／标准上下文／表单；扫描全部和 Tab 自动采用注册项，不修改工作区调度和结果界面。
- 大层级可实现 IIncrementalAssetCheckModule，在文件内部让出编辑器执行权；迭代器释放必须清理临时资源，只有完整检查后的文件计入统计。预制体／场景模块已采用此方式。 编辑器在每次更新内按约8毫秒预算推进多个步骤，避免分批检查被编辑器帧率拖慢；单次 Unity 原生调用仍可能超过该预算。
- 共用 SerializedReferenceChecks 识别失效引用；类型模块决定检查哪些对象和字段。
- 规则通过 TypeCache 发现，类型模块仍在 AssetCheckCatalog 显式注册；不提供规则 DSL、隐藏的优先级或额外的规则启停配置。报告上下文包含规则程序集指纹，规则变化后旧报告需要重新扫描。

## AB 资源大小与独立分析构建

AB 分析页支持选择已有 report，或明确点击“构建 AB 并分析”。构建复用 July Release 的当前平台和既有配置，产物位于Library/July/Release/Analysis；不触发 AOT/热更编译、正式产物清理、StreamingAssets/CDN 复制、上传或玩家导出。需要项目已配置 Release 且 DLL 输入可用。

选择某个包后，右侧“包内资源”显示每项的**本包未压缩数据大小**，从大到小排列；资源检查表新增可点击排序的大小列。全资源视图按实际入包副本显示“合计入包大小”，筛选某个包时显示“本包大小”。文件的问题随资源保持分组，大小排序不会被问题优先分组打乱；部分统计与未统计放在完整统计之后。

统计包含资源实际写出的对象、子对象、音频/纹理等独立数据，独立依赖资源不重复计入引用者，生成纹理只计一次。压缩 AB 大小、未压缩资源数据和运行时内存属于不同口径；不能用资源大小直接当下载大小或内存。包侧可展开查看生成数据、结构及未归属占用。未知显示“未统计”，部分显示已知大小和原因，不用 0 代替未知。

大小来自与 report 配套的 `<report>.sizes.json`，当前工程资源修改不会更新旧报告大小。无快照的旧报告仍可分析依赖和检查当前资源配置；失败或损坏的读取保留当前查看结果。入包规则继续完整复用资源检查标准，**不应用普通扫描的范围和忽略名单**；普通资源检查的忽略、修复和快照行为保持。

本包通过单向 Editor 依赖使用 `com.july.release` 的构建和统计契约；结果展示仍复用现有 AssetCheckResultsView/Model，不提供入包资源的修复或忽略操作。

### 多报告历史与对比

完整分析后，每份 report 独立保存到 `July/AssetCheck/BundleReports/<报告名_短指纹>/`。以原 report 字节的完整 SHA256 判断身份：同内容报告复制/移动仍是一份；同名不同内容分别保存。同报告只保留最新完整检查，取消/失败不覆盖它，不保存多次检查历史。

每个目录包含 `record.json`（轻量列表元数据）、`inspection.json`（原 report 字节、大小快照、最新完整检查及标准/时间）和 `view.json`（筛选、排序、分类、选中项与展开状态）。原 report 字节以 Base64 归档，大小 JSON 与检查结果放在同一个原子替换的快照里，避免事实与检查不一致；不复制 AB 文件。新目录完整写好后才发布。查看状态单独保存，关闭较旧的历史视图不会覆盖后来完成的检查。

从“历史”选择记录并点击“查看”，无需原构建目录，不扫描工程、不构建 AB。“重检资源”按当前显示的归档 report 确定入包范围，检查当前工程；完整结束后更新这一份历史。“选择 .report / 开始分析”用于读取新的外部构建报告。入包检查仍不应用普通目录范围或忽略名单，普通资源检查页的规则与忽略行为不变。

点击“结果对比”，选择基线与目标后比较，支持“AB 变化 / 资源变化”、搜索与只看变化。AB 按逻辑包名匹配，显示新增/删除、自身大小、报告依赖、去重依赖闭包、含依赖总计、循环和资源清单变化。资源优先按 GUID 匹配（无 GUID 时按路径），显示新增/不再入包、路径/所属包、各物理副本未压缩合计与检查证据变化。右侧明细列出依赖/资源变化及问题记录新增、消失、内容变化。

整包为压缩后的包文件大小，资源为未压缩实际写出数据，两种数值不混合。资源部分/未知大小不计算差值；未知与 0、未入包分开显示。问题按规则、子对象 ID、位置/属性和目标对齐，拆分/合并目标与输入顺序不制造假差异；显示名/源路径改名不改变规则证据身份。平台、Package、Unity/Yoo 版本或检查标准不同会提示比较边界，不把记录消失直接称为修复，也不把体积差异直接称为优化收益。

完整检查快照保存在项目根目录 `July/AssetCheck/BundleReports/`，可提交 Git 供团队读取；个人查看状态与最近选择仍保存在 `Library/July/AssetCheck/BundleReports/`，删除 Library 不会清除共享历史。单个损坏记录明确提示，其他记录仍可选择。比较只读取归档快照，不查询当前工程依赖、不修改资源或触发构建。旧版单份缓存需要重新读取原 report 完成一次分析后加入多报告历史。

### 入包资源结果的目录显示筛选

“资源检查结果”提供目录输入、“使用选中目录”和“全部目录”。路径以 Assets 或 Packages 开头，输入后回车/移出焦点应用，默认包含子目录；留空显示全部。按表格保存的 report 资源路径筛选，不查询目录是否仍存在，不随当前资源移动自动改变。与资源分类、所属 AB、搜索、状态筛选取交集，类型页签与未归类计数按当前目录/所属包统计；结果区注明全报告、当前目录、当前分类及当前显示数量。

目录仅是显示状态，不改变检查输入、报告事实或普通忽略名单；每份 report 的 view.json 单独记忆，旧查看状态缺少此字段时默认全部目录。读取另一份新报告默认全部，同一报告重检保留当前目录。“清除筛选”同时清除目录、所属包、搜索和状态；“全部目录”仅清除目录。

资源检查结果的“需要关注”汇总所有非“通过”条目：违规、未能检查、未完成或优化候选。混合状态每个文件只显示一条，保留原始状态和证据；仍与目录、分类、所属包、搜索和问题类型筛选取交集。

## Editor 缓存与共享

普通检查快照放在 `July/AssetCheck/Reports/`；入包分析的 `record.json` 和 `inspection.json` 放在 `July/AssetCheck/BundleReports/<报告ID>/`。对应的 `view.json` 与 `last.json` 仍在 `Library/July/AssetCheck/BundleReports/`，只复制 July 目录即可读取历史结果，无个人状态时使用默认视图。归档保留报告名及原始报告内容，不依赖生成者电脑上的构建路径。浏览历史只更新 Library，不改写共享证据。现有配置资产与项目设置位置不变。旧缓存仅作一次性迁移，不保留旧目录读取路径。

已有缓存迁移：将旧 `Library/July/AssetCheck/Reports/` 中的模块 JSON 复制到 `July/AssetCheck/Reports/`；将旧 `BundleReports/<报告ID>/` 中的 `record.json`、`inspection.json` 复制到 `July/AssetCheck/BundleReports/<报告ID>/`。`view.json`、`last.json` 留在 Library。不要用旧文件覆盖已存在的新缓存；旧包仍在使用时保留旧副本，项目更新到新包后可清理旧共享数据副本。
