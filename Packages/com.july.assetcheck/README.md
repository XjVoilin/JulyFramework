# July 资源检查

Unity 2022.3 编辑器资源检查工具。入口：**JulyGF → 资源管理 → 资源检查**。UI Toolkit，无运行时代码，无 JulyArch 或第三方 UI 依赖；声明 Unity 内置 Audio、JSON 模块依赖。未使用 URP 的项目也可以安装，URP 模块不会引入包依赖。

## 使用

1. 公共平台默认「小游戏」，纹理目标明确包含 WebGL、MiniGame、WeixinMiniGame。项目配置的构建目标按引擎确定：普通 Unity 使用 WebGL，团结 TUANJIE_1_5_OR_NEWER 使用 MiniGame，不切换当前构建目标。
2. 七个 Tab：贴图、模型、材质、预制体／场景、音频、URP、项目设置。检查当前类型或检查全部；注册且适用的规则全部执行，不提供规则启停开关。
3. 资源目录限制普通资源收集；URP 按 Graphics 和目标平台启用的 Quality 档收集关联管线及 Renderer，项目设置始终检查全项目配置。不会递归扫描目录外的普通资源依赖。
4. 每类标准在折叠区域修改。允许格式以集合设置，修改目标单独选择。只展示问题和未能验证的结果，通过仅计数；没有搜索、详情页或严重程度。
5. 结果以文件为主行，单问题直接显示，多问题内联展开；文件名优先，目录按列宽显示，空间不足时才省略前段，悬停显示完整路径。贴图、模型／Mesh 和材质类型的文件主行显示 32×32 缩略图，保持原图比例和透明度；普通贴图直接显示已导入纹理，模型、材质和图集使用 Unity 原生异步预览，不可用时显示资源图标，不主动打包图集或修改导入设置；复合资源文件显示该文件的整体预览。仅按可见虚拟行加载，行复用时清空旧预览，资源移动后按 GUID 更新，展开的问题子行不重复显示。点击缩略图或文件名直接选中资源，子问题名称可定位具体对象；文件主行直接显示“忽略”，按整个文件跳过检查。文件、问题、当前值、允许／要求四列表头均可点击排序，再次点击切换升降序，数值按大小比较。文件保持分组，多问题文件使用该列最小值排序，组内问题也按该列排序。支持问题类型筛选。筛选不关闭规则。勾选按文件标识保存，排序不会把选择转移到其他文件，筛选或换报告清空选择。仅未验证文件默认折叠，混合结果不重复计文件。Tab 有报告时始终显示问题文件数量，过期仍保留原数字和结果列表；没有检查记录显示“—”。当前页总览及悬停提示说明过期后需重新检查才能修改，修改权限及报告失效机制保持。“修改全部”处理当前 Tab 的全部已确认可修改问题，不受筛选和折叠影响；“修改选中”只处理勾选文件中符合筛选的已确认问题；未验证目标通过“设为标准”或右键菜单明确处理。
窗口沿用 Unity 原生字体与控件，提供深浅主题配色。顶部集中平台、范围与检查入口；Tab 数字仅表示已确认的问题文件数，概览单独显示问题、仅未验证、通过及忽略。上次快照与过期等状态独立提示。点击文件名选中资源，忽略直接显示为文件主行按钮；未验证目标仍可通过右键明确设为标准。配置文件和报告目录收进设置菜单。

6. 在 Project 中右键 Assets 下的具体文件夹 → **JulyGF → 资源检查 → 忽略文件夹／取消忽略文件夹**，支持多选目录。同一批选择父子目录时只新增最上层目录记录，和选择顺序无关；之前单独建立的子目录记录保留。单选未忽略目录仅启用“忽略”，已有独立忽略记录仅启用“取消忽略”；多选状态混合时两项均可用，仅处理对应状态的目录。继承上级忽略且没有独立记录的子目录两项均不可用，需在对应上级取消；展开右键菜单只读取配置，不创建或升级磁盘文件。目录忽略递归作用于全部类型，以文件夹 GUID 保存，移动或改名后仍有效；同名路径前缀不会误匹配。取消只移除所选目录自身的记录，保留上级、子目录和单文件的独立忽略；要恢复被上级覆盖的目录，请在对应上级取消。可在窗口的“已忽略资源”中查看与恢复。操作后重新扫描更新结果；检查或修改期间禁止变更目录忽略。不修改资源文件。

7. 当前报告可定位到子 Mesh／材质和问题组件；过期报告不按旧层级定位组件，仍可定位资源文件或有效子资源。可以单条修改、修改选中项、修改当前类型全部可修改项。修改前重读状态，只修改仍然不符合标准的对应设置，同一文件合并保存／导入；贴图（含图集）每批最多处理 20 个文件，通过 Unity 原生批处理集中导入，结束本批导入后更新进度并允许取消，所有批次结束后复查。每批通过 finally 恢复导入，取消或失败保留已保存的修改；当前批次导入期间仍可能阻塞。其他类型保持原有逐文件处理。

## 第一版规则与默认标准

| 类型 | 规则／默认标准 | 自动修改及影响 |
| --- | --- | --- |
| 贴图 | 允许 ASTC 6×6／8×8，修改目标6×6；MiniGame、WeixinMiniGame 必须启用平台覆盖 | 缺少小游戏覆盖属于已确认问题，纳入“修改全部”；补齐或修正对应平台，不改 Default 和其他平台 |
| 贴图 | 导入长边 ≤1024 | 按源尺寸、NPOT 缩放及有效平台 Max Size 判断是否超限；降低对应平台 Max Size，不改源图片 |
| 贴图 | Read/Write 禁止 | 关闭，影响该贴图所有平台的 CPU 可读性 |
| SpriteAtlas | 允许 ASTC 6×6／8×8，修改目标6×6，页面 Max Size ≤2048，Read/Write 禁止 | 格式／尺寸仅改目标覆盖，可读性影响所有平台；保留其他图集选项。配置保存后由后续图集打包采用，不执行全项目打包 |
| 模型 | 每 Mesh ≤2000 三角面 | 人工处理，不自动减面 |
| 模型 | Read/Write、导入灯光、导入相机、自动碰撞体均禁止 | 关闭对应导入选项，对整个模型文件、所有平台生效 |
| 材质 | Shader 有效，资源引用有效 | 人工恢复，不替换 Shader、不清空引用 |
| 预制体／场景 | 无 Missing Script，持久化引用有效 | 包含源 Prefab 丢失；人工恢复，不删除组件 |
| 音频 | 当前导入采样率 ≤44100Hz、声道 ≤2 | 仅检查，不模拟各小游戏 SDK 的音频实现，不自动修改 |
| URP | HDR、Depth Texture、Opaque Texture 禁止 | 关闭，影响该管线的全部使用者及相关效果 |
| URP | MSAA ≤1（关闭），Render Scale ≤1.0，SRP Batcher 必须开启 | 修改对应管线选项，不提高原本低于上限的数值 |
| URP | 主光源阴影允许，分辨率 ≤512、距离 ≤50、级联 ≤1；软阴影禁止 | 关闭或降低相应设置，可能影响阴影表现 |
| URP | 附加光源 Disabled，附加光源阴影禁止 | 按标准设置，可能影响照明和投影 |
| URP | 默认 Renderer 索引、Renderer 和 Feature 引用有效 | 人工恢复，不移除正常 Feature |
| 项目设置 | Color Space Linear；目标 Graphics API 手动指定 OpenGLES3 | 仅检查，修改使用 Unity 设置或已有发布工具 |
| 项目设置 | 目标默认质量档有效；Graphics／Quality 管线引用有效 | 仅检查；正常 Built-in 空引用或 Quality 回退合法 |

允许表示可以开启，不会强制每个资源开启。以上数值是可修改的项目标准，不是帧率、内存或平台兼容性的保证。关闭的 URP 功能不因残留的从属参数报错。URP 检查管线配置本身，不推断相机、Feature 或运行时代码的所有最终行为。

贴图与图集的 MiniGame、WeixinMiniGame 未启用平台覆盖时，显示“未配置平台覆盖”，计为问题并纳入“修改全部”。已配置且允许的格式保留；已启用覆盖但 Automatic 无法解析的目标仍为未验证，不随“修改全部”改写，可明确“设为标准”。WebGL 保持按有效格式检查，不强制建立覆盖。

## 完整性与扫描边界

- 正常未赋值的对象引用不报错；问题行包括对象层级、组件和字段。
- 嵌套／场景 Prefab 的继承问题归源资源，使用者的覆盖问题归使用者，避免重复报告；源资源不在扫描目录时不会为了它自动扩大扫描范围。
- 当前有未保存修改的场景或 Prefab 模式资源标记未能验证。未打开的场景以 additive 方式临时读取，随后关闭且不保存；保留原有场景、活动场景和选择。层级遍历分批执行，可中途取消并清理临时场景；Unity 原生打开／导入单次调用仍可能阻塞，也无法隔离项目自带的编辑器回调。
- 普通 Unity 无法解析团结目标 Automatic 或图集 Automatic 未得到有效格式时明确标记未能验证，可按明确标准写入覆盖后复查；扫描不会主动打包图集验证。
- URP 使用 Unity 2022.3／URP 14 的已知序列化字段读取配置。缺失字段标记未能验证，不反射猜测版本；不需要对 URP 程序集的编译依赖。光源枚举编码集中转换，保留配置 JSON 的既有语义；按 Forward／Forward+／2D 判断光照规则是否生效。Forward+ 与附加光源标准冲突时要求人工调整 Renderer，不提供无效的开关修改。批量修改先处理光源模式，再判断从属阴影参数，保留已失效功能的原有参数。
- 三角面统计不为检查开启 Read/Write，四边形计作两个三角面。独立 Mesh 不执行模型导入规则。

## 项目规则扩展

在项目的 Editor 程序集中引用 `July.AssetCheck.Editor`，实现所需 Context 的规则接口即可参与检查，无特性、手动注册、规则 ID 或版本配置：

```csharp
internal sealed class ExampleLayerRule : IAssetCheckRule<PrefabSceneCheckContext>
{
    public void Check(PrefabSceneCheckContext context)
    {
        if (context.IsPrefab && context.GameObject.name == "Example" && context.GameObject.layer != 31)
            context.Report(context.GameObject, "layer", "节点图层错误",
                context.GameObject.layer.ToString(), "31", "m_Layer");
    }
}
```

- Workspace 拥有 Module，Module 拥有规则实例。静态缓存仅保存发现的类型与构建标识；内置、项目规则统一发现、创建和执行，无两份注册表或合并排重。
- 问题统一由 Context 收集，在加入结果时校验修复条件并关联产生规则。规则无法直接访问结果列表；内置稳定标识与项目 `Report` 共用同一收集路径，调度器不再事后遍历结果补写归属。
- 一个 Module 固定一种 Context：`TextureCheckContext`、`ModelCheckContext`、`MaterialCheckContext`、`PrefabSceneCheckContext`、`AudioCheckContext`、`UrpCheckContext`、`ProjectCheckContext`。规则不加载资源、不保存 Context，也不修改检查输入。
- 所有非抽象、封闭的规则实现都参与发现，访问权限不决定是否启用。具体规则必须提供无参构造（可以非公开）；构造契约或规则执行失败明确中止检查。规则之间不依赖执行顺序。
- 模型导入选项与 URP 数值表是规则内部的参数化检查项，不实现规则接口。一个规则可以报告多条问题；原内置问题标识、平台目标及修复语义保留。
- `TextureCheckContext` 用 `IsAtlas` 区分图集与导入贴图，分别提供 Atlas 或 Importer。`UrpCheckContext` 提供当前 SerializedObject，以 `IsPipeline` 区分管线与 Renderer；Facts 仅在管线结构验证成功时提供。
- `Report` 的 code 在当前规则内保持稳定；框架自动补充程序集／类型标识、文件标识和对象位置。框架不会按继承关系自动过滤项目规则：内置引用完整性规则继续归属源 Prefab，而依赖使用者层级的业务规则可以报告继承节点。
- 需要修复的规则可实现 `IAssetCheckFix<TContext>`，并以 `canFix: true` 报告可修复项。当前支持保存修改的 Module 是贴图、模型、URP；其余 Module 保持人工处理。修复由产生当前问题的规则执行，沿用修改前重新检查、平台目标限制、保存／导入和修改后复查。
- 报告上下文包含参与规则的类型及程序集构建标识；重新编译、添加或移除规则后，旧快照会要求重新检查。

## 修改与忽略

资源修改影响它的全部使用者，目录范围不会限制共享资源的影响。Read/Write 关闭可能影响运行时 CPU 读取；关闭导入灯光／相机／碰撞体或 URP 功能可能改变行为及画面。

普通 Unity 2022.3 的纹理接口会对团结目标 ASTC 写入报错。团结目标沿用原有实现：由原生接口初始化条目，再用 SerializedObject 仅修改已有条目的标量字段，不增删序列化平台数组、不反射、不编辑 meta 文本、不抑制错误日志。只改尺寸时保留原来的格式。

忽略记录可指向**整个文件或文件夹**，跨类型、跨平台生效；目录记录递归覆盖其下资源。普通资源按 GUID 跟踪移动或改名，ProjectSettings 按稳定的项目相对路径记录。忽略后跳过全部规则，不计通过，全局名单在每个 Tab 折叠展示且可恢复。忽略模型文件同时排除该文件中的全部 Mesh、导入检查及其他适用检查；没有按规则忽略和自动失效。文件和目录的直接／继承排除共用 AssetCheckExclusions；已被目录覆盖的旧问题不会再生成冗余单文件记录。恢复不存在的记录是无副作用操作。被上级目录覆盖的独立记录显示“仍被上级目录忽略”，按钮为“移除记录”，并提示具体上级来源；已删除资源也可移除记录。

## 配置与报告

窗口首次打开创建项目根目录 AssetCheckSettings.json，与 Assets 同级，可纳入 Git。配置版本3，旧版1／2首次加载时迁移，保留模型、其他标准及忽略名单。原默认6×6扩展为允许6×6和8×8、修改目标6×6；旧自定义目标保留为单一允许格式。修改目标必须属于允许集合，已允许的8×8不会被改成6×6。无效 JSON、Git 冲突、未知版本和外部修改不会被默认配置覆盖。

忽略变更立即清理内存和保存结果中已知的被忽略问题，并更新可准确计算的文件统计；报告过期时清空旧勾选。恢复及目录范围变更仍需重新扫描。快照没有通过文件的完整标识，无法准确重算的统计明确标记过期，不伪造新结果。报告上下文包含顺序无关的忽略名单标识，关闭窗口期间修改名单也会在重开时识别；载入时按当前名单清理旧问题，但保留原扫描范围和标准上下文。URP 等全项目类型也跟踪已收集但被忽略的输入，移出忽略目录时，无论扫描中还是扫描后都使结果过期。

标准、范围、资源导入／删除／移动、已检查依赖变化、场景未保存修改和外部配置变化会使相关报告过期，报告显示扫描时间；过期状态只能由重新检查解除。全项目配置报告不因普通资源目录变化而过期。报告会区分通过、问题、忽略和未能验证，记录取消／未完成／失败，过期或未完成报告不能用于修改。操作显示修改／跳过文件数和复查结果；取消或失败前已经保存的修改保留，并明确提示重新检查。扫描结果自动保存到 Library/JulyAssetCheck/Reports，每模块一个固定 JSON（Texture、Model、Material、PrefabScene、Audio、Urp、Project），只覆盖该模块的最新结果，不记录历史，也不写入 Git 管理的项目配置。开始新检查时写入 Scanning 状态，完成／取消／失败时更新最终状态和已完成文件的结果；忽略和报告过期也同步保存。文件记录原扫描平台、范围、标准上下文、时间、统计和问题行，打开窗口自动恢复为只读快照；快照不能触发修改，必须先重新扫描。旧报告格式1仍可读，新报告格式2保留各目标的未验证状态，防止修改范围混淆。缓存损坏按模块明确提示，不覆盖原文件，也不影响其他模块。关闭窗口后不持续监听新变化。写入采用临时文件替换，保存失败明确提示并保留内存结果。删除 Library 可清理这些本机数据。Tab 和折叠状态放在 SessionState。

## 扩展方式

- AssetCheckWorkspace 只负责配置、任务、忽略、报告和完整修改流程；AssetCheckWindow 负责公共展示与用户操作。
- IAssetCheckModule 维持 Collect／Check／Fix 三个入口。收集返回检查对象标识，普通资源是 GUID，项目配置是稳定路径，AssetCheckTarget 统一解析，不伪造 GUID。
- 新增规则实现对应上下文的 IAssetCheckRule<TContext>，提供无参构造，即可由 Unity TypeCache 自动发现；需要修复时实现 IAssetCheckFix<TContext>，且模块本身必须允许保存。项目编辑器程序集中的规则同样可被发现。类型自行读取事实，规则自行判断，各类型不需要采用同一种事实结构。规则实例归各模块和工作区所有，只共享不可变的发现元数据。
- 新类型增加 Kind 与必要标准、实现模块、在所属类型目录提供标准表单，在 AssetCheckCatalog 一次注册名称／范围／标准上下文／表单；扫描全部和 Tab 自动采用注册项，不修改工作区调度和结果界面。
- 大层级可实现 IIncrementalAssetCheckModule，在文件内部让出编辑器执行权；迭代器释放必须清理临时资源，只有完整检查后的文件计入统计。预制体／场景模块已采用此方式。 编辑器在每次更新内按约8毫秒预算推进多个步骤，避免分批检查被编辑器帧率拖慢；单次 Unity 原生调用仍可能超过该预算。
- 共用 SerializedReferenceChecks 识别失效引用；类型模块决定检查哪些对象和字段。
- 规则通过 TypeCache 发现，类型模块仍在 AssetCheckCatalog 显式注册；不提供规则 DSL、隐藏的优先级或额外的规则启停配置。报告上下文包含规则程序集指纹，规则变化后旧报告需要重新扫描。
